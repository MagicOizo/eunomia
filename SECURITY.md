# Security policy

Eunomia stores health data, so security reports are taken seriously.

## Supported versions

Only the latest release receives fixes. Previews (`X.Y.Z-slice.N`) and older releases do not;
update to the latest release first and check whether the problem still exists.

## Reporting a vulnerability

**Please do not open a public issue.** Report it privately through GitHub instead:
[Report a vulnerability](https://github.com/MagicOizo/eunomia/security/advisories/new). Only the
maintainer can see the report.

A helpful report contains:

- the affected version (shown in the footer and under System > Settings),
- what an attacker can do, and which access they need for it (none, a user account, an admin
  account),
- the steps to reproduce it, ideally against a fresh instance with made-up data,
- if you have one, an idea for the fix.

Never include real personal or health data from an instance in the report.

## What to expect

Eunomia is maintained by one person in their spare time, so there are no guaranteed response
times. You will get an answer, and a confirmed vulnerability is fixed in a patch release whose
release notes credit you — unless you prefer not to be named.
